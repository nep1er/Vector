# Руководство по расширениям Vector

Документ для двух задач:

* **Защита проекта** — разделы 1–4 и 10–11: что такое расширение, зачем оно, как устроено и почему безопасно.
* **Разработка** — разделы 5–9: как написать, проверить и опубликовать своё расширение, и как доработать саму систему.

Краткий справочник (права, лимиты, развёртывание) — в [extensions.md](extensions.md). Здесь — подробное объяснение с нуля.

---

## 1. Что такое расширение и зачем оно

**Расширение** — это маленькое веб-приложение (HTML + JS + CSS в одном `.zip`), которое пользователи подключают к **своему проекту** в Vector. Оно добавляет то, чего нет в ядре:

* **страницу** в проекте (кнопка на левой панели) — например, «Зависимости задач» или «График сроков»;
* **блок в окне задачи** (панель) — например, «Зависимости» внутри карточки;
* **правила («стражи»)** — расширение может запретить завершить задачу, пока не выполнена другая.

Идея как у плагинов в Figma или Trello Power-Ups: ядро остаётся маленьким, а специфичные функции делают сами пользователи.

**Главное ограничение — безопасность.** Чужой код нельзя запускать с доступом к паролям, токенам и данным. Поэтому:

* расширение работает в **изолированной песочнице** (iframe) и не видит ни токен, ни cookie, ни сеть;
* всё, что ему нужно от Vector, оно получает через **мост** (`postMessage`) и только в рамках **выданных прав**;
* на сервере **код расширений никогда не выполняется** — сервер только хранит и отдаёт их файлы.

## 2. Общая схема

```
┌─────────────────────────── Браузер пользователя ────────────────────────────┐
│                                                                             │
│  Vector (React)                              iframe sandbox="allow-scripts"│
│  ┌──────────────────────────┐   postMessage ┌──────────────────────────┐   │
│  │ ExtensionFrame.tsx       │◄─────────────►│ Расширение (HTML/JS)     │   │
│  │  • проверка источника    │  запрос/ответ │  vector-sdk.js           │   │
│  │  • проверка прав         │               │  window.vector.*         │   │
│  │  • лимит 40 вызовов/10 с │               └──────────────────────────┘   │
│  │  • вызов API с токеном   │                          ▲ файлы             │
│  └─────────────┬────────────┘                          │ /ext/<версия>/..  │
└────────────────┼───────────────────────────────────────┼───────────────────┘
                 │ REST + JWT                            │ (отдельный origin, CSP)
                 ▼                                       │
        ┌──────────────────────────── Сервер (Express) ──┴─────────┐
        │ extensionRoutes      — каталог, библиотека, установки,   │
        │                        модерация, данные, журнал         │
        │ extensionServeRoutes — раздача файлов расширения         │
        │ ExtensionRepository  — SQL по расширениям                │
        │ ExtensionGuardRepository — «стражи» (правила ядра)       │
        │ utils/extensionPackage.js — проверка zip, манифеста      │
        │ utils/extensionStore.js   — файлы на диске               │
        └───────────────────────────┬──────────────────────────────┘
                                    ▼
                              PostgreSQL (extension*, user_extension,
                              project_extension, extension_data …)
```

Ключевой принцип: **расширение ничего не делает само — оно просит, а Vector решает**. Каждый запрос проверяется дважды: на клиенте (право выдано проектом?) и на сервере (есть ли у пользователя роль для этого действия?).

## 3. Жизненный цикл расширения

| Шаг | Кто | Что происходит | Где в коде |
|---|---|---|---|
| 1. Загрузка | Разработчик | Загружает `.zip` («Расширения → Мои разработки»). Сначала **пробная проверка** (dry-run) с отчётом ошибок и предупреждений, затем публикация | `UploadModal.tsx` → `POST /api/extensions` → `analyzePackage()` |
| 2. Модерация | Модератор | Видит версию в очереди, читает исходники, запускает **демо** (кнопка на странице расширения; тестовые данные, без доступа к проекту), одобряет или отклоняет с причиной | `ModerationTab.tsx`, `/api/moderation/*` |
| 3. Каталог | Пользователь | Одобренное расширение видно в каталоге. «Добавить» кладёт его в **личную библиотеку** | `CatalogTab.tsx`, `user_extension` |
| 4. Установка | Админ проекта | «Настройки проекта → Расширения»: подключает из своей библиотеки и **выдаёт права** (можно не все). Версия фиксируется | `ExtensionsTab.tsx`, `project_extension` |
| 5. Работа | Все участники | Страница/панель появляются в проекте, расширение запускается в песочнице | `ExtensionFrame.tsx` |
| 6. Обновление | Разработчик → админ | Новая версия требует новой модерации. Если запрашивает **новые права** — админ проекта должен явно согласиться | `PATCH …/projects/:id/:extId`, `…/update` |

Статусы версии: `PENDING` → `APPROVED` / `REJECTED`. Статусы расширения: `ACTIVE` / `REMOVED`. Если автора **банят**, его расширения перестают запускаться (файлы не отдаются), админы проектов получают уведомление.

### Роли платформы

| Роль | Откуда берётся | Что может |
|---|---|---|
| Администратор | e-mail в `PLATFORM_ADMIN_EMAILS` (серверная переменная) | всё, что модератор, + назначать модераторов |
| Модератор | назначает администратор (`platform_roles`) | проверять версии, удалять расширения, банить авторов, закрывать жалобы |

Эти роли **не дают доступа к содержимому проектов** — только к управлению каталогом.

## 4. Модель безопасности (для защиты)

Вопрос комиссии: *«А если расширение вредоносное?»* Ответ — пять уровней защиты:

1. **Проверка пакета при загрузке** (`utils/extensionPackage.js`): защита от zip-slip (`..` в путях), символических ссылок, zip-бомб (степень сжатия ≤ 100), зашифрованных записей, скрытых файлов, подмены типа файла. В HTML запрещены inline-скрипты, внешние ресурсы (`http://`, `//`), `iframe/object/embed/form/base`, `onclick=`-обработчики, `javascript:`. Подозрительный JS (`eval`, `new Function`, `fetch`, `XMLHttpRequest` …) даёт **предупреждение** модератору.
2. **Модерация человеком**: версия не доступна никому, пока её не одобрили.
3. **Песочница браузера**: `<iframe sandbox="allow-scripts">` **без** `allow-same-origin` — у страницы «пустой» origin, она не может читать localStorage/cookie/токен Vector, не может открыть окна и отправить форму.
4. **Строгая CSP** на файлах расширения: `default-src 'none'; script-src 'self'; connect-src 'none'; …` — **сеть закрыта** (даже если бы код попытался `fetch`, браузер заблокирует), внешние скрипты и картинки запрещены. Файлы отдаются с отдельного origin.
5. **Мост с правами**: единственный канал наружу. Проверяются источник сообщения, право на метод, принадлежность `id` проекту (расширение не может обратиться к чужой задаче), частота вызовов. Эффективные права = **выданные проектом ∩ права самого пользователя**: расширение не увидит больше, чем видит пользователь, и не сделает больше, чем разрешает его роль. Все обращения пишутся в **журнал проекта**.

Дополнительно: каждый запрос файла заново проверяет статус (удалено/забанен/не одобрено — перестаёт отдаваться); лимит загрузок — 10 версий в час на пользователя.

## 5. Быстрый старт: первое расширение за 10 минут

Сделаем расширение **«Статистика статусов»**: страница, которая показывает, сколько задач в каждом статусе.

### 5.1 Структура

```
status-stats/
├── manifest.json
├── index.html
├── app.js
├── style.css
├── icon.svg
└── vector-sdk.js     ← скопировать из extensions/sdk/vector-sdk.js
```

### 5.2 manifest.json

```json
{
  "apiVersion": 1,
  "id": "status-stats",
  "name": "Статистика статусов",
  "version": "1.0.0",
  "description": "Сколько задач в каждом статусе",
  "author": "Ваше имя",
  "icon": "icon.svg",
  "permissions": ["tasks:read", "ui:view"],
  "views": [{ "id": "main", "title": "Статистика", "entry": "index.html" }]
}
```

### 5.3 index.html

```html
<!doctype html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Статистика статусов</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <h1>Статистика статусов</h1>
  <div id="out">Загрузка…</div>
  <!-- Скрипты — ТОЛЬКО файлами, inline-скрипты запрещены -->
  <script src="vector-sdk.js"></script>
  <script src="app.js"></script>
</body>
</html>
```

### 5.4 app.js

```js
vector.ready(function (ctx) {
  // ctx = { projectId, user, theme, permissions, ... }
  Promise.all([vector.tasks.list(), vector.tasks.statuses()]).then(function (r) {
    var tasks = r[0], statuses = r[1];
    var out = document.getElementById('out');
    out.textContent = '';
    statuses.forEach(function (s) {
      var n = tasks.filter(function (t) { return t.status_id === s.id; }).length;
      var row = document.createElement('div');
      row.textContent = s.name + ': ' + n;     // textContent, не innerHTML!
      out.appendChild(row);
    });
  }).catch(function (e) { document.getElementById('out').textContent = 'Ошибка: ' + e.message; });
});
```

### 5.5 style.css

```css
body { margin: 0; padding: 24px; background: var(--v-bg, #fff); color: var(--v-text, #222);
       font: 14px/1.4 var(--v-font, system-ui); }
```

### 5.6 Упаковка и загрузка

1. Заархивируйте **содержимое** папки (в корне архива должен лежать `manifest.json`, **без** вложенной папки): в Windows — выделить файлы → «Отправить → Сжатая ZIP-папка»; в терминале `cd status-stats && zip -r ../status-stats.zip .`
2. «Расширения → Мои разработки → Загрузить» — появится отчёт проверки.
3. Опубликуйте. Для разработки на своём компьютере задайте в `server/.env` `EXTENSIONS_AUTO_APPROVE=true` — версии одобряются без модератора.
4. Добавьте из каталога в библиотеку → в проекте «Настройки → Расширения» подключите и выдайте права → кнопка расширения появится на левой панели.

## 6. Манифест — справочник

| Поле | Обяз. | Описание |
|---|---|---|
| `apiVersion` | да | Всегда `1` |
| `id` | да | Уникальный код на платформе: `^[a-z][a-z0-9-]{2,47}$` |
| `name` | да | Название для людей |
| `version` | да | `x.y.z`; каждая новая загрузка должна быть **выше** предыдущей (сравнение по semver) |
| `description` | да | До 300 символов |
| `author` | да | Имя автора |
| `icon` | нет | Путь к SVG/PNG внутри архива |
| `permissions` | да | Массив прав из раздела 7 |
| `views` | * | Страницы проекта (до 10): `{id, title, entry}`. Нужно право `ui:view` |
| `taskPanels` | * | Блоки в окне задачи (до 3): `{id, title, entry, height}`, высота 80–600 px. Нужно право `ui:task-panel` |
| `guards` | нет | Правила (до 3), см. раздел 8 |

\* нужна хотя бы одна страница или панель. Неизвестные поля манифеста отклоняются.

**Лимиты пакета:** zip ≤ 10 МБ, распаковано ≤ 20 МБ, файл ≤ 5 МБ, ≤ 300 файлов, глубина путей ≤ 6, манифест ≤ 64 КБ. **Разрешённые типы:** `html js mjs css json txt md png jpg jpeg gif webp ico svg woff woff2`.

## 7. Права и SDK

### 7.1 Права

| Право | Что даёт | Методы SDK |
|---|---|---|
| `tasks:read` | читать дерево задач | `tasks.list`, `tasks.statuses` |
| `tasks:write` | менять даты/статусы | `tasks.updateDates`, `tasks.setStatus` |
| `kanban:read` | читать доски ToDo | `kanban.board` |
| `kanban:write` | двигать карточки | `kanban.moveCard` |
| `members:read` | участники и их роли | `members.list` |
| `storage:read` | названия файлов хранилища | `storage.list` |
| `data:read` | читать свои данные в проекте | `data.list` |
| `data:write` | писать свои данные (только руководителям, на сервере право EXECUTE) | `data.set`, `data.remove` |
| `guard:task-status` | включает «стражей» | — |
| `ui:view` | страницы | `ui.resize` |
| `ui:task-panel` | панель в задаче | `ui.resize`, `ui.autoResize` |

**Принцип минимальных прав:** просите только то, что нужно — админ проекта видит список и может отказаться.

### 7.2 Справочник SDK (`window.vector`)

Подключение: `<script src="vector-sdk.js"></script>`. Все методы возвращают **Promise**.

```js
vector.ready(cb)        // cb(ctx) вызывается, когда мост готов
                        // ctx: { projectId, viewId, user:{id,username}, theme:'light'|'dark',
                        //        permissions:[...], taskId? (в панели задачи), demo:boolean }
vector.onTheme(cb)      // cb('light'|'dark') при смене темы приложения
vector.call(method, params)   // низкоуровневый вызов (обычно не нужен)

vector.tasks.list()                       // [{id,type,title,description,start_date,end_date,parent_id,status_id}]
vector.tasks.statuses()                   // [{id,name}]
vector.tasks.updateDates(id, start, end)  // 'YYYY-MM-DD'
vector.tasks.setStatus(id, statusId)      // может быть отклонён «стражем» (ошибка 409)

vector.kanban.board(todoId)               // колонки с карточками
vector.kanban.moveCard(cardId, columnId, index)

vector.members.list()                     // [{user_id,username,avatar_url,roles[]}]
vector.storage.list()                     // [{id,name,files:[{id,name}]}]

vector.data.list(collection)              // [{key, value}]
vector.data.set(collection, key, value)
vector.data.remove(collection, key)

vector.ui.resize(height)                  // 80–600 px (панель)
vector.ui.autoResize()                    // панель сама подгоняет высоту под содержимое
```

**Собственное хранилище (`data.*`).** Это единственное место, куда расширение может писать. Коллекция: `^[a-z][a-z0-9_]{0,31}$`, ключ ≤ 64 символа, значение — JSON ≤ 16 КБ, до 5000 записей на расширение в проекте. Данные принадлежат паре «проект + расширение» (таблица `extension_data`) — основные таблицы расширению недоступны.

**Статусы задач (`status_id`):** 1 Выполнено, 2 В процессе, 3 В плане, 4 Просрочено, 5 Заморожено, 6 Неактивно.

**Ошибки:** `Error` с полем `code`: `DENIED` (нет права или чужой id), `RATE_LIMIT` (больше 40 вызовов за 10 с), `UNKNOWN` (нет такого метода), `ERROR` (прочее; текст — в `message`).

### 7.3 Оформление: цвета приложения

Vector передаёт цвета как CSS-переменные на `<html>`: `--v-bg`, `--v-surface`, `--v-surface2`, `--v-text`, `--v-muted`, `--v-border`, `--v-accent`, `--v-on-accent`, `--v-danger`, `--v-success`, `--v-input`, `--v-radius`, `--v-font`. Используйте их с запасным значением — тогда расширение автоматически совпадает с любой из четырёх тем:

```css
.card { background: var(--v-surface, #fff); color: var(--v-text, #222);
        border: 1px solid var(--v-border, #ddd); border-radius: var(--v-radius, 6px); }
```

### 7.4 Правила безопасного кода расширения

* Выводите данные через `textContent`, а не `innerHTML` (названия задач пишут люди).
* Не используйте `eval`, `new Function`, `fetch`, `XMLHttpRequest`, `WebSocket` — сети всё равно нет, а модератор увидит предупреждение.
* Не подключайте внешние библиотеки/шрифты/картинки по ссылке — кладите файлы в архив.
* Обрабатывайте `catch`: права могут быть отозваны, роль пользователя может не разрешать действие.
* В панели задачи: у `body` нет внешних отступов + `vector.ui.autoResize()`.

## 8. Стражи (guards): расширение меняет поведение ядра

Расширение не выполняет код на сервере, но может **объявить правило в манифесте**, которое ядро применяет само:

```json
"guards": [
  { "type": "task-blocked-by", "collection": "deps", "field": "blockedBy", "statuses": [1, 2], "cards": true }
]
```

**Как работает (на примере «Менеджера зависимостей»):**

1. Расширение хранит связи в своей коллекции `deps`: ключ — id задачи, значение — `{ "blockedBy": [id, id] }` (через `vector.data.set`).
2. Когда пользователь меняет статус задачи на значение из `statuses` (1 «Выполнено», 2 «В процессе»), ядро (`ExtensionGuardRepository.checkTaskStatus`) читает запись `deps/<id задачи>`, берёт список из поля `blockedBy` и проверяет статусы этих задач **по основной таблице `task`**.
3. Если хоть одна не выполнена — ядро отвечает **409**: «Нельзя начать работу: сначала завершите задачу «…»». Сообщение показывается пользователю.
4. При `"cards": true` то же правило действует для карточек Канбана (нельзя завершить карточку или вынести её из первой колонки).

Правило включено, только если: расширение установлено и включено, версия одобрена, автор не забанен, проекту выдано `guard:task-status`. В манифесте для стражей обязательны права `guard:task-status` и `data:write`.

Сейчас поддержан один тип — `task-blocked-by`. Как добавить свой — раздел 10.3.

## 9. Тестирование и отладка

* **Демо-режим.** Автор и модераторы на странице расширения (даже до одобрения версии) нажимают «Демо» — расширение запускается так: `ctx.demo === true`, данные тестовые, доступа к реальному проекту нет. Удобно проверять оформление.
* **Консоль браузера.** F12 → Console: ошибки JS расширения видны там (выберите контекст iframe). Ошибки моста приходят как `Error` в `catch`.
* **Журнал проекта.** «Настройки → Расширения → Журнал» — какие методы вызывало расширение и с каким результатом.
* **Проверка пакета без публикации.** Окно загрузки сначала показывает отчёт (dry-run).
* **Типичные ошибки:**

| Симптом | Причина |
|---|---|
| «Скрипты в HTML запрещены» | есть `<script>…</script>` или `onclick=` — вынесите в `.js` файл, вешайте обработчики через `addEventListener` |
| `DENIED: Нет права tasks:read` | право не заявлено в манифесте или не выдано проектом |
| `Нет ответа от Vector` | страница открыта не внутри Vector (двойной клик по `index.html`) — мост работает только во фрейме |
| Расширение «пропало» из проекта | версия не одобрена / автор забанен / расширение отключено |
| Панель обрезана или с пустым местом | не вызван `vector.ui.autoResize()` или у `body` есть margin |
| «версия должна быть выше» | поднимите `version` в манифесте |

## 10. Как устроена система изнутри (для доработки)

### 10.1 Где что лежит

| Часть | Файл |
|---|---|
| Проверка zip и манифеста, список прав, лимиты | `server/utils/extensionPackage.js` |

### 10.2 Протокол моста

Сообщения — объекты с полем `vector: 1`.

```
Расширение → Vector   { vector:1, event:'hello' }                      ← при загрузке
Vector → Расширение   { vector:1, event:'ready', context:{…} }         ← можно работать
Расширение → Vector   { vector:1, id:7, method:'tasks.list', params:{} }
Vector → Расширение   { vector:1, id:7, ok:true,  result:[…] }
                      { vector:1, id:7, ok:false, error:{code,message} }
Vector → Расширение   { vector:1, event:'theme', theme:'dark', colors:{…} }
```

Мост (`ExtensionFrame.tsx`) на каждое сообщение: 1) проверяет `ev.source === iframe.contentWindow`; 2) считает частоту (скользящее окно 10 с, максимум 40); 3) ищет обработчик в таблице `handlers` — **неизвестный метод отклоняется**; 4) обработчик проверяет право (`need('tasks:read')`) и принадлежность id известным задачам проекта; 5) вызывает обычный REST API **с токеном пользователя** — значит, срабатывает серверный RBAC; 6) записывает вызов в очередь журнала.

### 10.3 Рецепты доработок

**Добавить новый метод SDK** (например, `tasks.search(query)`):

1. `server/utils/extensionPackage.js` — если нужно новое право, добавить в `PERMISSIONS`;
2. `client/src/utils/extensions.ts` — человеческая подпись права;
3. `ExtensionFrame.tsx` — обработчик в `handlers['tasks.search']`: `need(право)` → вызов `api…` → вернуть данные;
4. `extensions/sdk/vector-sdk.js` — обёртка `search: function (q) { return call('tasks.search', { q: q }); }` (и обновить копии SDK в `examples/*`);
5. раздел 7 этого документа.

**Добавить новый тип стража** (например, `task-requires-field`): объявить схему в `validateManifest` (`extensionPackage.js`) → обработать тип в `ExtensionGuardRepository.activeGuards` и добавить проверку → вызвать её там, где меняется состояние (`TaskRepository.updateStatus`, `KanbanRepository.moveCard/updateCardStatus` уже вызывают проверки стражей) → описать в разделе 8.

**Добавить новое место для UI** (например, панель в карточке Канбана): поле в манифесте + проверка в `validateManifest` → рендер в `CardModal.tsx` через `ExtensionFrame` (по образцу `TaskExtensionPanels.tsx`) → передать `context` (id карточки).

**Поменять лимиты** — `LIMITS` в `extensionPackage.js`; частоту вызовов — константы `RATE_LIMIT` / `RATE_WINDOW_MS` в `ExtensionFrame.tsx`.

**Новая версия API** — поднять `apiVersion` и поддерживать старую: расширения фиксируют версию в манифесте.

Папка `extensions/examples/task-dependencies/` (готовый архив — `task-dependencies.zip`).

| Файл | Роль |

| `manifest.json` | права `tasks:read data:read data:write guard:task-status ui:task-panel ui:view`; страница `overview`, панель `deps` (высота 260), страж `task-blocked-by` над коллекцией `deps` |

**Поток данных при добавлении связи:** панель → `Deps.save(taskId, [..ids])` → `vector.data.set('deps', '42', {blockedBy:[7]})` → мост проверяет `data:write` → `PUT` в `extension_data` (сервер: только EXECUTE) → запись в журнал. Позже при попытке завершить задачу 42 ядро читает эту же запись и, если задача 7 не выполнена, отвечает 409.

**Другой пример:** `extensions/examples/task-timeline/` — страница «График сроков» и панель «Сроки» (только чтение: `tasks:read`, `ui:view`, `ui:task-panel`) — самый простой образец.

## 12. Вопросы к защите — краткие ответы

* **Чем расширения отличаются от обычных функций ядра?** Их пишут сторонние разработчики, они подключаются в проект по желанию админа и ограничены правами.
* **Может ли расширение украсть данные?** Нет: нет сети (CSP `connect-src 'none'`), нет доступа к токену (sandbox без `allow-same-origin`), видит только то, что разрешил проект и роль пользователя.
* **Может ли оно что-то сломать?** Менять оно может только через мост и только то, на что есть право и роль; всё в журнале; админ проекта может отключить или удалить расширение в один клик.
* **Что если автор — злоумышленник?** Модерация до публикации, жалобы, бан автора (расширения перестают запускаться).
* **Как расширение влияет на логику ядра, не выполняя серверный код?** Декларативные «стражи»: расширение описывает правило и хранит данные, ядро применяет правило само.
* **Как добавить возможность?** Раздел 10.3 — новый метод SDK / новый тип стража / новое место UI.
