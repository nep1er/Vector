# Расширения Vector

Расширение — это небольшое статическое веб-приложение (HTML/JS/CSS), которое работает **внутри проекта** в изолированной песочнице. Серверного кода пользователей в версии 1 нет: расширения не могут выполнять код на сервере и ходить в сеть.

## Как это устроено

1. **Разработчик** загружает `.zip` на странице «Расширения → Мои разработки». Сервер проверяет архив (структура, типы файлов, размеры, опасные конструкции) и показывает отчёт.
2. **Модератор** видит версию в очереди, читает исходники, запускает демо и одобряет или отклоняет её с причиной.
3. **Пользователь** добавляет одобренное расширение в личную библиотеку («Каталог → Добавить»).
4. **Администратор проекта** в «Настройки → Расширения» подключает расширение из своей библиотеки и **выдаёт права**. Версия фиксируется; новая версия с дополнительными правами требует явного согласия.
5. Расширение появляется в проекте: кнопка на левой панели (страницы, право `ui:view`) и/или блок в окне задачи (право `ui:task-panel`).

### Роли платформы

| Роль | Кто | Что может |
|---|---|---|
| Администратор | e-mail из `PLATFORM_ADMIN_EMAILS` | назначать и снимать модераторов; права модератора тоже есть |
| Модератор | назначается администратором | проверять версии, удалять расширения, банить **автора** (только в части расширений), закрывать жалобы |

Бан автора не затрагивает аккаунт, проекты и работу в них: у автора закрывается только публикация, а его расширения перестают запускаться (статус «Автор заблокирован») до снятия бана. Глобальные роли **не дают доступа к содержимому проектов**.

## Пакет

В корне архива — `manifest.json` и файлы расширения (без вложенной папки-обёртки).

```json
{
  "apiVersion": 1,
  "id": "task-timeline",
  "name": "Сроки задач",
  "version": "1.0.0",
  "description": "До 300 символов",
  "author": "Имя",
  "icon": "icon.svg",
  "permissions": ["tasks:read", "ui:view", "ui:task-panel"],
  "views": [{ "id": "timeline", "title": "График сроков", "entry": "index.html" }],
  "taskPanels": [{ "id": "dates", "title": "Сроки", "entry": "panel.html", "height": 110 }]
}
```

* `id` — `^[a-z][a-z0-9-]{2,47}$`, уникален на платформе; `version` — `x.y.z`, каждая новая загрузка должна быть выше предыдущей.
* Минимум одна страница (`views`, до 10) или панель (`taskPanels`, до 3, высота 80–600). Страницам нужно право `ui:view`, панелям — `ui:task-panel`.

### Ограничения

Архив ≤ 10 МБ, распаковано ≤ 20 МБ, файл ≤ 5 МБ, ≤ 300 файлов, глубина ≤ 6, степень сжатия ≤ 100. Разрешены: `html js mjs css json txt md png jpg jpeg gif webp ico svg woff woff2`.

Отклоняются: пути с `..`, абсолютные и Windows-пути, символические ссылки, зашифрованные записи, скрытые файлы, дубликаты имён (без учёта регистра), несовпадение типа картинки с содержимым, не-UTF-8 текст; в HTML — inline-скрипты, внешние ресурсы (`http(s)://`, `//`), `iframe/object/embed/form/base`, `meta refresh`, `on*`-обработчики, `javascript:`; в SVG — `script`, `foreignObject`, обработчики. Подозрительный JS (`eval`, `new Function`, `fetch`, `XMLHttpRequest`…) даёт **предупреждение** модератору.

Скрипты подключайте файлами: `<script src="app.js"></script>`. Стили — файлом или атрибутом `style`.

## Права

| Право | Что даёт |
|---|---|
| `tasks:read` | `tasks.list`, `tasks.statuses` |
| `tasks:write` | `tasks.updateDates`, `tasks.setStatus` |
| `kanban:read` | `kanban.board` |
| `kanban:write` | `kanban.moveCard` |
| `members:read` | `members.list` |
| `storage:read` | `storage.list` (названия, без содержимого файлов) |
| `data:read` | `data.list` — чтение собственных данных расширения в проекте |
| `data:write` | `data.set`, `data.remove` — запись собственных данных (на сервере только право EXECUTE, т. е. руководителям) |
| `guard:task-status` | включает «стражей» из манифеста (см. ниже) |
| `ui:view` | страницы проекта |
| `ui:task-panel` | панель в окне задачи, `ui.resize` |

Эффективные права = **выданные проектом ∩ права запустившего пользователя**. Расширение не может увидеть больше, чем видит сам пользователь (скрытые от его роли задачи остаются скрытыми), и сделать больше, чем ему позволяет роль.

## SDK

Скопируйте `extensions/sdk/vector-sdk.js` в архив и подключите. Он создаёт `window.vector`:

```js
vector.ready(function (ctx) {          // ctx: {projectId, viewId, user, theme, permissions, taskId?, demo}
  vector.tasks.list().then(render);    // [{id,type,title,description,start_date,end_date,parent_id,status_id}]
});
vector.tasks.statuses();               // [{id,name}]
vector.tasks.updateDates(id, '2026-11-01', '2026-11-10');
vector.tasks.setStatus(id, statusId);
vector.kanban.board(todoId);           // колонки с карточками
vector.kanban.moveCard(cardId, columnId, index);
vector.data.list('deps');              // [{key, value}] — коллекция a-z0-9_, ключ до 64 симв., значение до 16 КБ, до 5000 записей
vector.data.set('deps', '42', {blockedBy: [7]});
vector.data.remove('deps', '42');
vector.members.list();                 // [{user_id,username,avatar_url,roles[]}]
vector.storage.list();                 // [{id,name,files:[{id,name}]}]
vector.ui.resize(height);              // панель в задаче, 80–600 px
vector.ui.autoResize();                // панель сама подстраивает высоту (body без внешних отступов)
vector.onTheme(function (t) {});       // 'light' | 'dark' (атрибут data-theme ставится на <html> автоматически)
```

Цвета приложения доступны как CSS-переменные `--v-bg`, `--v-surface`, `--v-surface2`, `--v-text`, `--v-muted`, `--v-border`, `--v-accent`, `--v-on-accent`, `--v-danger`, `--v-success`, `--v-input`, `--v-radius`, `--v-font` — расширение совпадает с любой темой Vector (см. `style.css` в примерах).

Ошибки приходят как `Error` с `code`: `DENIED` (нет права/чужой id), `RATE_LIMIT` (более 40 вызовов за 10 с), `UNKNOWN`, `ERROR`.

Готовый пример — `extensions/examples/task-timeline/` (и собранный `task-timeline.zip`).

## Стражи (guards): расширение вмешивается в логику ядра

Расширение **не выполняет код на сервере**, но может объявить в манифесте декларативное правило, которое ядро применяет само:

```json
"guards": [{ "type": "task-blocked-by", "collection": "deps", "field": "blockedBy", "statuses": [1, 2], "cards": true }]
```

Для `task-blocked-by` ядро перед сменой статуса задачи на один из `statuses` (1 «Выполнено», 2 «В процессе» …) читает запись `deps/<id задачи>` из собственных данных расширения, берёт список id из поля `blockedBy` и, если среди этих задач есть невыполненные, отвечает ошибкой 409: «Нельзя начать работу: сначала завершите задачу «…»». При `cards: true` то же правило действует для карточек Канбана ToDo-задачи: нельзя завершить карточку или перенести её из первой колонки. Правило работает, только если расширение установлено, включено, одобрено, автор не забанен и проект выдал право `guard:task-status`. Нужны также `data:write` и (для UI) `tasks:read`. Основные таблицы расширению недоступны — только `extension_data`.

Пример — `extensions/examples/task-dependencies/` («Менеджер зависимостей задач»).

## Безопасность

* Код запускается в `<iframe sandbox="allow-scripts">` **без** `allow-same-origin`: origin «пустой», cookie/localStorage/токен приложения недоступны.
* Файлы отдаются с отдельного origin со строгой CSP: `default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'none'; form-action 'none'; base-uri 'none'; frame-ancestors <клиент>`, `X-Content-Type-Options: nosniff`.
* Единственный канал наружу — `postMessage`-мост в доверенном коде хоста: проверяются источник сообщения, выданные права, принадлежность id проекту, частота вызовов; сервер дополнительно проверяет RBAC по токену пользователя. Все обращения пишутся в журнал проекта (Настройки → Расширения → Журнал).
* Раздача файлов каждый раз проверяет статус: расширение удалено, автор забанен или версия не одобрена — файлы перестают отдаваться, в проекте расширение помечается недоступным, администраторы проектов получают уведомление.
* Загрузки ограничены: 10 версий в час на пользователя.

### Развёртывание

* `PLATFORM_ADMIN_EMAILS=admin@example.com` — администраторы платформы.
* `EXTENSIONS_AUTO_APPROVE=true` — только для разработки: версии одобряются без модератора.
* Отдавайте `/ext/*` и `/extp/*` с **отдельного домена** (например `ext.vector.example`), укажите его в клиенте `VITE_EXT_URL`, а в сервере `CLIENT_ORIGIN=https://vector.example` (для `frame-ancestors`). Общий домен с приложением снижает изоляцию.
* Файлы хранятся в `STORAGE_DIR/extensions/<versionId>/` (вне веб-корня).
