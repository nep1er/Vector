# Vector Desktop (WPF)

Здесь находится нативный Windows-клиент Vector. Desktop изолирован от Web-клиента `client/` и API-сервера `server/`.

## Текущий экран

Главная страница «Проекты» перенесена по структуре Web-клиента:

- боковая панель шириной 264 px, оригинальный логотип, активное состояние навигации и профиль внизу;
- заголовок, количество проектов, поиск и кнопка создания в одной строке;
- карточки проектов с теми же пропорциями, градиентами, изображениями, описанием и датой создания;
- состояние пустого списка и диалог создания проекта;
- загрузка проектов, профиля и количества непрочитанных уведомлений через существующие API-эндпоинты.

Визуальная сверка на Windows ещё не выполнена. Цель — добиться совпадения с Web выше 95% после сравнения скриншотов при одинаковом разрешении и теме.

## Требования

- Windows
- .NET 9 SDK
- запущенный API-сервер Vector

## Настройка API

По умолчанию Desktop обращается к API по адресу `http://localhost:5000`. При необходимости адрес можно изменить переменной окружения `VECTOR_API_URL`.

Для текущего этапа токен авторизации читается из переменной окружения `VECTOR_TOKEN` или из локального файла, который не нужно добавлять в Git:

`%AppData%\\Vector\\session.json`

Содержимое файла:

```json
{
  "token": "ВАШ_ТОКЕН_VECTOR"
}
```

Токен можно получить из действующей Web-сессии. Не отправляй его в чат и не добавляй в репозиторий.

## Запуск

Открой `Vector.Desktop/Vector.Desktop.sln` в Visual Studio или выполни из папки `desktop`:

```powershell
dotnet run --project .\\Vector.Desktop\\Vector.Desktop.csproj
```

## Правила портирования

- Весь Desktop-код хранить внутри `desktop/`.
- Не менять Web-клиент и API-сервер в рамках портирования.
- Использовать Web-реализацию и общие дизайн-токены как источник поведения и визуального оформления.
- Переносить экраны постепенно и сверять каждый с Web-версией до завершения.
